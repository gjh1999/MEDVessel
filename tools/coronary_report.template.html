先明确我们正在比较什么

本项目处理的是三维冠脉 CTA 的管腔二值分割。二维导管造影 XCA 的序列跟踪、三维增强图、中心线和管腔 Mask 是不同输出。不能把中心线的 overlap、带距离容差的 F 值、二维像素 Dice 和三维体积 Dice 排成一张“准确率排行榜”。

最直接的学习对象：VMTK 的冠脉 Level Set 流程。它明确区分“增强用于初始化”和“在原始灰度上演化边界”。CATE 是同一方法家族的冠脉应用工具；ThinVesselSegmentation、RORPO 适合学习或替换特征模块；VCO 展示二维序列的图模型约束。

本轮能核实的直接三维冠脉传统流程集中在 VMTK 家族。下面列出 5 个论文—代码入口，不把同家族封装和通用增强组件冒称为 5 种独立、完整的三维冠脉分割算法。这些外部工程核对了论文与代码说明，未在本机逐一构建，也没有复现它们的论文成绩。

02 · 从增强到分割，传统路线真正差在哪里

当前实现：硬门限决定哪里可以生长

输入CTA + 种子
特征多尺度 Frangi
决策响应 / 强度门限
输出种子可达区域
Eligible(x) = [V(x) ≥ 0.08] ∧ [100 ≤ I(x) ≤ 900]
Mask = Eligible 中包含指定种子的连通分量（26 邻域）

它回答“这个体素是否允许通过”，没有优化“整条边界应该在哪里”。一旦局部桥接到参考之外的亮结构，后者只要满足门限就会被一并接纳。一个大的连通分量可能同时包含正确血管与错误区域。

VMTK：增强先帮助初始化，再利用原图边界

初始化增强图 + 端点
前沿传播Fast Marching
表面演化原图梯度 + 曲率
结果管腔表面 / Mask

这条路线给边界增加了图像梯度和几何平滑约束，端点、停止点可限制目标分支。它不保证永不泄漏，参数和交互仍然重要；但分割不再等同于对增强响应做连通阈值。具体输入约定见 官方冠脉流程。

路径 / 图模型：把局部响应变成代价与结构约束

“把增强当权重”通常发生在这类方法中：响应高的位置代价低，同时惩罚不合理的方向、断裂或对应关系。VCO 的图约束用于相邻 XCA 帧的中心线对应，不是本项目已实现的三维管腔分割。它值得学的是：局部像血管，和属于目标冠脉结构，是两种判断。

03 · 泛化诊断：先看精确率与召回率

本轮读取已保存的 source、vesselness、mask 和 reference，重新计算 TP / FP / FN；再用独立的 SciPy 26 邻域连通标记，从同一颗种子回放区域生长。11 例回放均与 C++ 保存的 Mask 逐体素一致，Dice 也与原指标一致。这证明当前门限和连通规则确实解释了输出，不等于证明所有上游滤波都没有数值误差。

Precision = TP / (TP + FP)　　Recall = TP / (TP + FN)
Dice = 2TP / (2TP + FP + FN)
病例Dice精确率召回率预测 / 参考体积主要表现
病例 111：Dice 0.2191，但召回率 0.9139。

它没有“漏掉九成血管”，而是精确率仅约 0.1245，预测体积约为参考的 7.34 倍。病例 106 也出现明显参考外扩张。图像支持错误区域被增强和连通传播纳入；具体涉及何种解剖结构还需逐层确认，不能只凭最大投影命名。

门限与连通性究竟漏掉了多少参考血管

新增病例平均保留参考体素 91.86%；仅因响应不足被挡住约 7.43%，两个条件都不满足约 0.23%，仅强度不符约 0.03%，满足条件但无法从种子到达约 0.44%。因此，灰度门限造成的目标损失和种子连通造成的漏分，在这批局部样例中都不是主要矛盾。

04 · 原因：哪些已证实，哪些还只是推测

已由代码与测量支持

缺少对参考外结构的拒绝能力

新病例召回高、精确率低；最差病例预测体积显著膨胀。Frangi 判断局部管状形态，不能独自识别“这是不是目标冠脉”。当前生长只检查响应和强度，没有原图边界停止项、背景停止点或解剖排除约束。

固定 low=0.08、c=100、强度范围及尺度由原病例出发，病例 1 的结果不能代表患者间变化；新增病例显示这种固定组合不稳定。

合理推测，尚未定位到独立因果

形态、对比度和边界采样变化

参考内强度中位数从病例 1 的约 348，变化到新增病例约 339～672；这些差异会影响固定 Frangi 强度参数和门限的响应。尺度范围、运动、钙化、重建核等也可能影响结果，但目前没有逐项控制实验，不能宣称它们就是主因。

需要检查 Hessian / 增强图与独立实现的一致性；本轮连通回放一致并没有完成这一项验证。

三组事后回放：简单放宽条件为什么不合适

固定原始增强图，不重算 Hessian；只改变接纳条件。下面是新增 10 例逐例指标的算术平均。它们属于解释失败的事后消融，不是在独立测试集上验证的算法提升。

回放条件平均 Dice平均精确率平均召回率说明

三件不应被误判成分割低分原因的事

  • 高阈值 0.2：这轮有显式种子，代码进入 seededRegionGrowing3D；高阈值不参与生长，只在自动选种子模式使用。修改它不会改变这批分割。
  • 短枝修剪 1 mm：作用于 Mask 之后的骨架，不能修复 Mask 的假阳性，也不直接改变分割 Dice。
  • 删除小连通域：11 例预测均为一个连通分量，错误区域已与目标相连；靠最小连通域体素数无法剪掉它。独立回放已包含 20 体素过滤，且与输出完全一致。
下一步传统算法改进应优先减少假阳性。先定位从正确血管进入错误区域的连接位置，尝试背景停止点、原图边界演化或约束传播；保留局部半径与细支召回检查。改参数或加约束后，应在开发集选配置，再另留未查看病例验证，不能把当前 11 例继续称为测试集。

05 · 如果用深度学习，会更好吗？

值得尝试，而且可能改善当前最明显的假阳性问题；但需要同条件验证。3D 网络可从更大的空间上下文学习目标与相似亮结构的区别，不必只依赖局部 Hessian 和固定门限。它也会受训练样本、标注习惯、扫描协议和域偏移影响，不能把“用了网络”视为泛化保证。

现有 11 例应该怎样使用

  1. 先做权重与病例划分审计。使用预训练模型前，核对当前编号是否出现在其训练集或验证集；若无法确认，只能标为演示，不报告独立测试性能。
  2. 保留患者级划分。同一病例的切片、裁剪块、不同标注版本必须在同一侧。2766 张切片仍然只有 11 个病例，不能随机打散切片制造大样本。
  3. 这 11 例已经成为开发数据。可以做流程验证或小规模微调探索，不能再凭这些已查看的结果证明最终泛化。训练新模型需要更多、来源更丰富的数据和未查看的评估病例。
  4. 输出接入原几何分析链。让网络先输出保持几何元数据的管腔 Mask，再复用已有 EDT、骨架、分支表和 Qt 展示。网络分割本身不需要强制依赖 Frangi。

传统与深度学习也可以结合

可比较 CTA → 3D 网络 → Mask 与 [CTA, Frangi] → 双通道网络 → Mask，或由网络提供概率 / 初始化，再做受约束的传统边界优化。增强作为额外通道不保证必然有效，应该以消融实验判断。现有算法与 Qt 工程仍可用于解释结果、检查拓扑和展示几何。

06 · 建议按这个顺序学习和实验

顺序具体工作能回答的问题
1复看病例 106、111 的原图、响应和三维错误区域；保存泄漏入口与边界切片错误是在增强阶段就产生，还是传播跨入了相邻结构？
2按 VMTK 官方冠脉教程跑一个相同分支，记录端点、停止点和交互耗时边界演化和人工约束能否抑制泄漏？交互预算是否公平？
3在开发集上试少量传统约束；或将 Frangi 换为另一增强组件做独立对照改进来自增强特征、定位约束还是分割决策？
4审计预训练数据重叠，再运行一个冠脉专用 3D 网络；暂不设计复杂新结构学习到的空间上下文能否减少参考外预测？
5锁定协议后，另取未查看病例；统一物理空间、目标范围、种子 / ROI 来源与后处理性能提升是否可推广，而不是来自更有利的输入？

报告同时看 Dice、精确率、召回率、clDice、HD95 和逐例失败；对冠脉树还应检查左右树、远端细支、错连与断裂。交互式方法与全自动方法应分别报告，不将参考辅助 ROI 的成绩当作自动全图性能。
